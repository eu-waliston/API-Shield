Threat Detection Engine

Análise comportamental, não apenas regras

O motor de detecção observa padrões ao longo do tempo e combina sinais independentes para identificar atividade de alto risco.

Authentication Attack

Excesso de falhas de autenticação em curto intervalo indica tentativa de brute force ou credential stuffing.

failed_loginthresholdwindow

Route Discovery Attack

Exploração sistemática de endpoints sensíveis em busca de superfície exposta.

/users/admin/internal/debug/config

Multi-Signal Correlation

Sinais isolados podem ser ruído. Combinados, revelam atividade de alto risco com muito mais precisão.

Policy Engine

Regras de segurança declarativas

Defina políticas em JSON simples: allow/deny, controle por rota, validação de escopo, bloqueios temporários e controles administrativos.

policies.json json 
[
  {
    "id": "block-admin-route",
    "enabled": true,
    "action": "deny",
    "match": {
      "routePrefix": "/admin"
    }
  }
]
  • ▸

    Allow / Deny rules

    Decisões explícitas de permissão ou bloqueio por regra.

  • ▸

    Route-based policies

    Políticas aplicadas por prefixo de rota ou endpoint específico.

  • ▸

    Scope validation

    Verificação de escopos do token JWT antes de liberar a requisição.

  • ▸

    Temporary blocking

    Bloqueios com expiração automática para contenção rápida.

  • ▸

    Administrative controls

    Endpoints administrativos protegidos por token dedicado.

Automated Response

Da detecção à contenção em milissegundos

Quando uma ameaça é identificada, o API Shield executa uma sequência defensiva automatizada.

STEP 01

Detecção

IP suspeito identificado pelo motor de análise comportamental.

STEP 02

Bloqueio temporário

Requisições do IP são negadas por uma janela de tempo definida.

STEP 03

Security Event

O incidente é registrado no Redis com todos os sinais correlacionados.

STEP 04

Revisão do administrador

Alertas são exibidos no dashboard para análise e ação humana.

Executando com Docker

Rodando em menos de dois minutos

Clone, configure os segredos e suba o ambiente completo com Docker Compose.

1

Clone o projeto

Repositório público no GitHub.

2

Crie o ambiente

Copie o .env.example para .env.

3

Gere seus segredos

Use openssl rand -hex 32 para cada chave.

4

Suba os containers

Build e execução em background.

5

Verifique a saúde

Um curl no endpoint /health confirma o funcionamento.

Nunca faça commit do arquivo .env. Gere segredos fortes e exclusivos para cada ambiente de execução.

terminal 
# 1. clonar
git clone https://github.com/eu-waliston/API-SHIELD.git
cd API-SHIELD

# 2. ambiente
cp .env.example .env

# 3. segredos
openssl rand -hex 32

# 4. subir
docker compose up --build -d

# 5. verificar
docker compose ps
curl http://127.0.0.1:3000/health

Security Considerations

Postura defensiva por padrão

O projeto segue boas práticas de desenvolvimento seguro — e documenta o que ainda é necessário para ambientes reais.

Aplicado no projeto

  • Containers não executam como root
  • Segredos nunca armazenados no código
  • Validação de entradas administrativas
  • Sem exposição de informações internas
  • Security headers via Helmet
  • Princípio do menor privilégio

Recomendado para produção

  • TLS obrigatório
  • Reverse proxy seguro
  • Monitoramento externo
  • Rotação periódica de credenciais
  • Pentest periódico
